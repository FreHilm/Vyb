## Goal

Phase 1 of improving merge/conflict handling. Today `ConflictResolver.tsx`
parses conflict hunks and offers four canned per-hunk decisions (ours / theirs
/ both-ot / both-to) but renders everything as plain `<pre>` blocks — there's
**no way to hand-edit** a hunk, which is exactly what the hard conflicts need.

Replace the static result view with an **editable Monaco editor** (reuse
`MonacoFileEditor`), keep the per-hunk accept buttons (they edit the result
model), and let the user freely tweak the merged text before saving + staging.
Also auto-open the resolver when an operation reports conflicts, so the flow
starts without a manual click on a banner pill.

This is the contained, de-risking step before the bigger 3-pane editor (T-059).

## Background

- `ConflictResolver.tsx` — marker parsing (`<<<<<<< ======= ||||||| >>>>>>>`),
  4 canned decisions, `<pre>` panes, `buildResolved()` → `saveFile` → `gitStage`.
- `MonacoFileEditor.tsx` — editable, syntax-highlighted, `onChange`/`onSave`,
  language auto-detect. Good fit for the result pane.
- `GIT_SHOW_STAGE` already reads base/ours/theirs (`:1:/:2:/:3:`).
- Conflicts surface in a banner (`git-ref-ops.tsx`); resolver is opened by
  clicking a conflicted-file pill — it does NOT auto-open.

## Acceptance Criteria

- [x] Per-hunk accept buttons still work and update the Monaco model.
- [x] User can hand-edit any part of the result; edits persist to save+stage.

- [x] Resolver auto-opens (or focuses) when merge/rebase/cherry-pick/revert

## Notes

Precursor to [[T-059]] (3-pane merge editor) and [[T-060]] (inline CodeLens +
smarter merges). Keep the Monaco wiring reusable so T-059 can lift it.

Design decisions confirmed with the user before building:
- Edit model: **live markers + find/replace** — editor seeded with the raw
  conflicted file; accept buttons splice into the live buffer; "conflicts
  left" = remaining markers (so manual edits count too).
- Layout: **single result editor + hunk toolbar** (left list of hunks with
  Ours / Theirs / Both buttons + jump; Monaco editor fills the rest).
- Auto-open: **UI-initiated ops only** (merge/rebase/cherry-pick/revert started
  from Vyb). Shell-driven conflicts still surface via the banner.
