## Goal

Be able to run multiple agents against the same project on different branches, using a GitFlow-style workflow.

This should be a per-profile setting. When enabled, dispatching a task from the Kanban board spawns a new agent thread instead of injecting into the regular agent. There should be an auto mode (Enter is sent automatically so the agent starts working) and a manual mode (the user can edit the prompt before pressing Enter). A new row appears under the parent profile in the sidebar, showing the task id and title.

When the agent finishes, it should remain visible; if the user navigates away after inspecting it, it should auto-remove. The Stop button removes it immediately.

The agent must work on an isolated copy of the repo (so the parent checkout stays clean). Git: create a feature branch, commit, push, and open a pull request.

## Progress

- Locked design via Q&A: `git worktree`, branch name `agent/<taskId>-<slug>`, worktree under `<userData>/parallel-agents/<profileId>/`, auto-push as a Settings toggle, Run/Edit per-task at dispatch (no Ordna change), `gh pr create --fill`, soft-delete 30s after inspection, no concurrency cap.
- Types: added `Profile.parallelAgentEnabled`, `AppSettings.parallelAgentAutoPush`, `ParallelAgent`/`ParallelAgentPhase` interfaces, six new IPC channels (`parallel:spawn|destroy|list|finish|change|exited`).
- Main: new `src/main/parallel-agent-manager.ts` with `spawn` (worktree + PTY), `destroy` (PTY kill + `git worktree remove --force` fallback to rmrf), `finish` (`git add -A && git commit && git push --force-with-lease && gh pr create --fill`). Wired into `ipc-handlers.ts`: PTY data feeds the status detector for `parallel:` ids, exit handler tears down worktrees, status detector callback bumps phases and auto-triggers `finish` on working→ready when auto-push is on.
- Preload + window.api: `spawnParallelAgent`, `destroyParallelAgent`, `listParallelAgents`, `finishParallelAgent`, `onParallelAgentChange`, `onParallelAgentExited`.
- Renderer dispatch: `onOrdnaTask` now checks `targetProfile.parallelAgentEnabled` — if true, calls `spawnParallelAgent` and stashes the prefixed task message in a ref. The buffered message is sent (with `\r`) only when the user clicks the row's ▶ Run button, giving per-task auto/manual control without modifying Ordna.
- UI: `Sidebar` renders sub-rows under each parent profile (`ParallelAgentRow`) with phase + live PTY status, ▶ Run (when awaiting) and ⏹ Stop controls. New `ParallelAgentTerminal` component owns each parallel agent's xterm.js view; `App.tsx` mounts one per agent and toggles them via CSS based on `selectedParallelId`. Clicking a parent profile row deselects the parallel agent so the regular `TerminalPane` reappears.
- Lifecycle: soft-delete timer of 30s starts when a `completed` agent has been inspected (selected) and the user has navigated away; cancelled if they return. Stop button fires immediate destroy + worktree teardown. App shutdown calls `destroyAll`.
- ProfileEditor: new "Run Kanban tasks in parallel agents" toggle. Settings → Ordna: new "Auto-push parallel agent branches" toggle.
- Out of scope (per agreement): GitLab/Bitbucket PRs, conflict-resolution automation, startup cleanup of orphaned worktrees from prior sessions.
- Verification: `npx tsc --noEmit` clean; `npm start` boots cleanly with the new bundles.
