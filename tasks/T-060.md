## Goal

Phase 3 — polish and power features on top of the merge editor, for lower
friction on simple conflicts and more control on big ones.

- **Inline CodeLens** in the normal file editor: open a conflicted working-tree
  file in `MonacoFileEditor` and render "Accept Current | Accept Incoming |
  Accept Both | Compare" CodeLens above each conflict region (the VS Code inline
  experience). Clicking edits the model to resolve that region.
- **Surface the base** (common ancestor) using `merge.conflictStyle=diff3` or
  the existing `:1` stage, so 3-way context is visible.
- **Bulk per-file actions**: "take all ours" / "take all theirs"
  (`git checkout --ours/--theirs <file>` then stage).
- **Merge preview / dry-run** before committing: `git merge --no-commit --no-ff`
  (or detect-conflicts-first) so the user sees what will land / whether it
  conflicts before starting.

## Background

- Needs a Monaco CodeLens provider + conflict-region decorations (some of this
  lands in [[T-059]] and can be reused).
- New IPC (4-place pattern): `GIT_CHECKOUT_OURS_THEIRS` (bulk), optionally
  `GIT_MERGE_FILE` (`git merge-file -p` for a clean 3-way recompute), and a
  merge-preview/dry-run channel. `GIT_SHOW_STAGE` already covers reading stages.

## Acceptance Criteria

- [x] Inline CodeLens actions on conflict regions in `MonacoFileEditor`
      resolve the region on click (Accept Current / Incoming / Both; edit-only).
      "Compare" deferred — it implies opening another view, out of edit-only scope.
- [x] Base/common-ancestor visible via a "Base" toggle that adds a read-only
      `:1` pane in the 3-pane view (per the clarifying answer; not diff3 rewrite).
- [x] Per-file bulk "take ours" / "take theirs" on the conflict-banner pills
      (`git checkout --ours/--theirs` + stage).
- [x] Merge preview / dry-run via `git merge-tree --write-tree` — "Preview
      merge…" menu item → dialog showing clean / conflicting files, with a
      "Merge now" button.
- [x] New IPC channels registered in all four places; `npx tsc --noEmit` clean.

## Notes

Depends on [[T-059]]. Pick items independently — inline CodeLens and bulk
actions are the highest-value; `git merge-file` and dry-run are nice-to-haves.

Design decisions confirmed with the user before building:
- **All four features** implemented.
- **CodeLens: FileExplorer editor, edit-only** — clicking edits the buffer; the
  normal save/stage flow is unchanged (no implicit git side effects).
- **Base: read-only `:1` pane via a toggle** in the 3-pane view (not a diff3
  marker rewrite).
- Bulk actions placed on the conflict-banner file pills; merge preview uses
  `git merge-tree` surfaced through a "Preview merge…" menu item + dialog.

`git merge-file` (mentioned in Background) was not needed — the editor-side
splice + `checkout --ours/--theirs` cover the same ground without rewriting
markers.
