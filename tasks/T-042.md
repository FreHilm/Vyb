## Goal

For users who sign their commits, surface signature status in the
commit graph and let the user toggle signing on / off per profile.

## Acceptance Criteria

- [x] Each row in the Tree tab gets a small signature indicator:
      verified (green), bad (red), unknown-validity (yellow). Unsigned
      stays icon-less. Tooltip shows the signer name and status code.
- [x] A "Sign commits" toggle lives next to the commit button in the
      Git panel (more discoverable per-repo than burying it in
      Settings → Functions, which is app-global). Writes
      `commit.gpgsign true|false` to the repo's local config.
- [x] When the underlying `git commit` fails (no GPG agent, signing
      misconfigured, etc.) the existing commit error banner surfaces
      git's own message — no extra plumbing needed because the toggle
      doesn't intercept the commit path.

## Notes

`git log --show-signature` for verification status (parse the
`gpg: …` lines). For the toggle, write to `.git/config` directly via
`git config --local commit.gpgsign true|false`.

## Progress

- 2026-05-14: Shipped. `GIT_LOG` now also emits `%G?` and `%GS` so
  every commit carries `sigStatus` (G/B/U/X/Y/R/E) + signer name; the
  Tree tab renders a small shield badge next to the subject (green
  verified, red bad, yellow unknown). Two new IPCs `git:getSignCommits`
  / `git:setSignCommits` read and toggle `commit.gpgsign` in the repo's
  local config, surfaced as a "Sign commits" checkbox under the
  commit button. GPG-agent failures bubble through the existing
  commit error banner.
