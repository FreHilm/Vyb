## Goal

Resize the editor text on the fly without diving into Settings.
`Cmd+=` bumps up, `Cmd+-` bumps down, `Cmd+0` resets. The current
size persists across app restarts so the user's preference is
remembered. Matches the muscle memory most editors and browsers
have wired up the same way.

## Acceptance Criteria

- [x] `Cmd+=` (and `Cmd++`) bumps editor font +1px, capped at 32px.
- [x] `Cmd+-` decreases -1px, floor at 8px.
- [x] `Cmd+0` resets to 13px.
- [x] Live across every CodeMirror instance — FileExplorer's tabs
      and ReadmeViewer's edit mode both read
      `var(--cm-editor-font-size)` so a single setProperty on
      `:root` updates them all at once.
- [x] Value persisted to `settings.editorFontSize` via
      `savePaneSizes`; hydrated on launch by the existing
      load-settings useEffect.
- [x] Editor row added to the Appearance font table so users can
      type a value directly.

## Notes

- CodeMirror's font size lives in the `EditorView.theme(...)`
  block at `FileExplorer.tsx:894-1024`. Replace the hardcoded
  `fontSize: '13px'` with a CSS variable (`var(--cm-font-size)`)
  driven from a setting; same trick the rest of the theme already
  uses for `--c-base` etc. ReadmeViewer's editor wires the same
  variable.
- Keybinding scope: keep it editor-local so we don't fight
  terminal Cmd+= / Cmd+- (xterm.js doesn't bind those, but stay
  safe by attaching the listener on the CodeMirror keymap rather
  than the window).
- The keys involved:
  - `Cmd+=` is the unshifted variant of `Cmd++` (the literal `+`
    key requires Shift on a US layout). Bind both `Mod-=` and
    `Mod-+` so either path works.
  - `Cmd+-` is straightforward.
  - `Cmd+0` is the zoom-reset convention.
- Don't tie this to the existing `profileFontSize` setting —
  that's the agent-list sidebar typography and serves a different
  purpose.

## Progress

- 2026-05-14: Shipped. New `settings.editorFontSize` (default 13).
  An App-level effect mirrors the value onto a `:root`
  `--cm-editor-font-size` CSS variable; FileExplorer's and
  ReadmeViewer's CodeMirror themes now reference
  `var(--cm-editor-font-size, ...)` instead of a hardcoded px
  value, so both editors update live the moment the variable
  changes.
  
  Keyboard: four entries added to FileExplorer's CodeMirror
  keymap — `Mod-=`, `Mod-+`, `Mod--`, `Mod-0`. They call a
  ref-shimmed `onAdjustEditorFontSize(delta)` provided by App,
  which clamps to [8, 32] and writes back through the debounced
  `savePaneSizes` path. Reset (`Cmd+0`) passes `delta === 0` and
  the App handler snaps the value to the 13px default.
  
  Settings → Appearance gets a new row in the font table so the
  size can be set manually without chording.
