## Goal

Resize the editor text on the fly without diving into Settings.
`Cmd+=` bumps up, `Cmd+-` bumps down, `Cmd+0` resets. The current
size persists across app restarts so the user's preference is
remembered. Matches the muscle memory most editors and browsers
have wired up the same way.

## Acceptance Criteria

- [ ] `Cmd+=` (and `Cmd++`) inside the editor pane increases font
      size by 1px, capped at a sensible max (e.g. 32px).
- [ ] `Cmd+-` decreases font size by 1px, floor at 8px.
- [ ] `Cmd+0` resets to the default (13px — current hardcoded
      value).
- [ ] New value applied live to the active editor and any other
      CodeMirror instances mounted at the same time (file tabs in
      FileExplorer, README's edit mode in ReadmeViewer).
- [ ] Value persisted to `settings.editorFontSize` via the
      existing `savePaneSizes` (debounced) path. Hydrated on app
      launch.
- [ ] Setting also surfaced in Settings → Appearance as a number
      input so the user can pick a size directly when they don't
      want to chord.

## Notes

- CodeMirror's font size lives in the `EditorView.theme(...)`
  block at `FileExplorer.tsx:894-1024`. Replace the hardcoded
  `fontSize: '13px'` with a CSS variable (`var(--cm-font-size)`)
  driven from a setting; same trick the rest of the theme already
  uses for `--c-base` etc. ReadmeViewer's editor wires the same
  variable.
- Keybinding scope: keep it editor-local so we don't fight
  terminal Cmd+= / Cmd+- (xterm.js doesn't bind those, but stay
  safe by attaching the listener on the CodeMirror keymap rather
  than the window).
- The keys involved:
  - `Cmd+=` is the unshifted variant of `Cmd++` (the literal `+`
    key requires Shift on a US layout). Bind both `Mod-=` and
    `Mod-+` so either path works.
  - `Cmd+-` is straightforward.
  - `Cmd+0` is the zoom-reset convention.
- Don't tie this to the existing `profileFontSize` setting —
  that's the agent-list sidebar typography and serves a different
  purpose.
