## Goal
In the file editor, when a file has been modified and the user undoes the change, the "modified" status should be cleared if the undo returns the document to its on-disk state.

## Acceptance Criteria

- [x] Editing a file flips the tab indicator to modified (`*`).
- [x] Undoing back to the on-disk content clears the `*` indicator and the Save button disables.
- [x] Subsequent edits re-flag the file as modified.

## Notes
The fix is already present in `src/renderer/components/FileExplorer.tsx` — landed in commit `1c092fd8` ("Added Ordna Kanban") on 2026-04-26.

Implementation:
- `savedContentRef` (line 311) — per-file on-disk baseline.
- `mountEditor` (lines 413–416) — captures the baseline the first time a file is mounted.
- `EditorView.updateListener` (lines 431–443) — on every `docChanged`, compares `update.state.doc.toString()` to the baseline; if they match, the path is removed from `modifiedSet` (this is the undo-to-clean path); otherwise added.
- `handleSave` / `handleSaveAs` (lines 372, 386) — refresh the baseline on save so subsequent edits-then-undo clear correctly.
- `handleRenameSubmit` (lines 743–747), `doCloseTab` (line 607), and the tab-reuse branch in `openInTab` (line 585) keep `savedContentRef` in sync with the tab/file lifecycle.

Verification:
- `npx tsc --noEmit` — no type errors.
- `npm start` — electron-forge bundle builds and launches successfully (Vite dev server up on :5173, main + preload bundled).
- Code trace: open file with disk content "X" → type "Y" → modifiedSet adds path; undo → doc returns to "X" → matches baseline → path removed from modifiedSet → tab `*` cleared and Save button disables (`activeIsModified` is false).

Caveat (out of scope for T-009): switching tabs creates a fresh `EditorState` in `mountEditor`, which discards the CodeMirror undo history. After a tab switch, undo can no longer reach the original on-disk state. If that becomes a problem, file a follow-up.
