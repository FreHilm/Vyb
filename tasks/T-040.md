## Goal

Show LFS-tracked files clearly in the Changes / file tree views, and
expose the most common LFS operations (locks, fetch, prune) so users
working in an LFS repo don't have to drop to the terminal.

## Acceptance Criteria

- [ ] In the file tree and Changes view, files matching the
      repository's `.gitattributes` LFS patterns get a small badge.
      *(V2 — needs lfsFiles set threaded through Changes + FileExplorer)*
- [x] Branches tab gains an "LFS" section. Body adapts: list locks
      + Fetch + Prune + Unlock/Force when configured; "doesn't use
      LFS" when installed but the repo has no LFS patterns; install
      link when LFS isn't on PATH.
- [x] Helpful empty state if LFS isn't installed (linkout to
      git-lfs.com via the existing `openUrl` bridge).

## Notes

`git lfs ls-files`, `git lfs locks`, `git lfs lock|unlock <file>`,
`git lfs fetch`, `git lfs prune`. All best-effort: if `git lfs` isn't
on PATH, gracefully hide the section.

## Progress

- 2026-05-14: Shipped. Six new IPCs cover the operations —
  `git:lfsInfo` (probes `git lfs version` for availability, then
  `git lfs ls-files` for configured/tracked counts),
  `git:lfsListLocks` (parses `git lfs locks --json` with a
  plain-text fallback), `git:lfsLock`, `git:lfsUnlock` (with `--force`
  param), `git:lfsFetch`, `git:lfsPrune`. All treat a missing
  `git lfs` extension as a soft failure so the empty state can
  render.
  
  New LFS section in the Branches tab shows the right body for each
  state: not installed → install link; installed but unused →
  message; in use → Fetch / Prune buttons plus a locks list with
  Unlock and Force buttons per row.
  
  Per-file LFS badges in Changes view + FileExplorer deferred to V2;
  those need an `lfsFiles` set threaded through several components.
