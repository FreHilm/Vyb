## Goal

A simple browser for `git reflog`. Recovery tool — when a user
accidentally amends / resets / branch-deletes and wants to find the
previous state, they shouldn't have to drop to the terminal.

## Acceptance Criteria

- [x] Tree tab gets a "Reflog" toggle that shows reflog entries as a
      flat list: selector, short-SHA, action, subject, relative time.
- [x] Right-click → Copy SHA, Checkout this state (detached), Reset
      current branch to here (disabled when detached).
- [x] Reset action goes through the existing confirm-with-options
      reset flow (soft / mixed / hard) — same `ops.onReset` from
      `useGitRefOps` the commit graph already uses.

## Notes

`git reflog --format=<porcelain>` for the data. Be mindful the reflog
is per-ref; default to `HEAD`'s reflog, with a small picker for other
refs if we want to extend later.

## Progress

- 2026-05-14: Shipped. New `git:reflog` IPC parses `git log -g` with
  NUL-separated fields (sha + selector + reflog subject + author
  date + commit subject), capped at 1000 entries. GitTree's toolbar
  gets a Reflog ↔ Commits toggle; the toggled view swaps the commit
  graph for a flat reflog list. Right-clicking a reflog row opens
  Copy SHA / Checkout this state / Reset to here — the latter two
  reuse the existing `ops.onCheckout` and `ops.onReset` from
  `useGitRefOps` so they pick up the same checkout-with-confirm and
  soft/mixed/hard reset flows the commit graph already drives.
