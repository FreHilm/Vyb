## Goal

Phase 2 — the headline improvement: a VS Code–style **3-pane merge editor**
built from Monaco editors (Monaco's npm package ships a 2-way diff editor and a
code editor, but NOT VS Code's 3-way merge widget — so we compose it).

Layout:

```
┌──────── Current (ours) ────────┬──────── Incoming (theirs) ────────┐
│ read-only Monaco, conflict     │ read-only Monaco, conflict        │
│ regions highlighted, per-region│ regions highlighted, per-region   │
│ [Accept Current] [+ Both]      │ [Accept Incoming] [+ Both]        │
├──────────────────── Result ────┴───────────────────────────────────┤
│ EDITABLE Monaco — seeded from the file, updates as regions are      │
│ accepted, fully hand-editable. This is what gets written + staged.  │
└─────────────────────────────────────────────────────────────────────┘
```

Sources from `GIT_SHOW_STAGE` (ours `:2`, theirs `:3`, base `:1`). Per-conflict
"accept" actions splice the chosen text into the Result model; a live
"N conflicts remaining" count gates "Apply & stage".

## Background

- Reuse the editable-result Monaco wiring from [[T-058]] for the Result pane.
- `MonacoDiffEditor.tsx` modified side is already editable; ours/theirs panes
  are read-only Monaco editors with conflict-region decorations.
- Need a small Monaco helper to decorate conflict regions and place the
  per-region action buttons (overlay widgets or glyph-margin actions).

## Notes

Depends on [[T-058]]. Polish items (inline CodeLens, bulk ours/theirs, diff3
base, merge preview, auto-open) live in [[T-060]].

Design decisions confirmed with the user before building:
- **Toggle between both views** — the T-058 single-editor view and the 3-pane
  view coexist; a header toggle switches them and the live buffer is preserved
  across the switch (re-seeded from `content`).
- **Full stage files** in the side panes — ours = `:2`, theirs = `:3`, shown
  read-only as scrollable context.
- **Floating Accept buttons on the Result regions** (Monaco content widgets),
  not on the side panes — avoids fragile hunk→full-file mapping. Side panes are
  pure context. (This adjusts the original AC wording, which put the actions on
  ours/theirs.)
