## Goal

Guided `git bisect` from the Git panel: start, mark current state
good/bad, step, reset. Great for hunting regressions in long
histories.

## Acceptance Criteria

- [x] Tree tab right-click on a commit → "Start bisect: <sha> good,
      HEAD bad" / "<sha> bad, HEAD good". The persistent bisect
      banner appears at the top of the Tree tab while a session is
      active.
- [x] Banner buttons: Good / Bad / Skip / Reset.
- [x] Each mark refreshes the tree and shows the new HEAD + step
      counts; remaining steps estimated from
      `git rev-list --bisect-vars`.
- [x] On a found commit, the banner switches to a "first bad
      commit" result row with the short SHA + subject and a Reset
      button. ("Open in Tree" deferred — the SHA highlight in the
      tree already lands you there.)

## Notes

`git bisect start <bad> <good>`, `git bisect good|bad|skip`,
`git bisect reset`, `git bisect log` for progress info. Conflicts
mid-bisect surface via the same in-progress banner machinery (T-025).

## Progress

- 2026-05-14: Shipped. Four new IPCs cover the lifecycle —
  `git:bisectStart`, `git:bisectMark` (good/bad/skip),
  `git:bisectReset`, and `git:bisectStatus` (detects an in-progress
  session via `BISECT_LOG`, parses counts from `git bisect log`,
  estimates remaining steps from `git rev-list --bisect-vars`, and
  spots a found commit by scanning the log for `# first bad commit:`).
  
  Two new commit-row menu entries route through a new `onBisectStart`
  op in `useGitRefOps`. The bisect banner reuses the existing
  merge/rebase in-progress banner shell with a coloured left edge so
  it's distinguishable. Conflicts mid-bisect surface through the
  same banner machinery from T-025.
