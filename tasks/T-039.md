## Goal

Make repositories that use submodules usable from the Git panel: list
them, see their state (in-sync / modified / uninitialised), init /
update / sync them, and open one as its own working profile.

## Acceptance Criteria

- [x] "Submodules" section in the Branches tab when `.gitmodules`
      exists at the repo root.
- [x] Per submodule: path, short SHA, describe, status pill +
      colour-coded dot (clean / modified / uninitialised / conflict).
- [x] Right-click: Init, Update, Update --remote, Sync URL, Show in
      Finder. *("Open as profile" deferred to V2 — needs ProfileEditor
      prefill plumbing.)*
- [ ] Changes tab shows submodule pointer changes as a single line
      "submodule X: a1b2c → c3d4e" with click-through. *(V2)*

## Notes

`git submodule status`, `git submodule init`, `git submodule update
--remote`, `git submodule sync`. The "open as profile" action can
reuse the existing Add Profile flow with the submodule's path
pre-filled.

## Progress

- 2026-05-14: Shipped. Four new IPCs — `git:submodulesList` parses
  `git submodule status` plus `.gitmodules` (for each name's url) so
  each row carries path, SHA, describe, status, and URL.
  `git:submoduleInit`, `git:submoduleUpdate` (with a `remote` flag
  for `--remote`), and `git:submoduleSync` round it out; all three
  validate the submodule path against `.gitmodules` so the user can't
  smuggle in a flag-like value.
  
  Branches-tab Submodules section appears whenever `.gitmodules`
  exists, with a colour-coded status dot + pill per row (clean /
  modified / uninitialised / conflict). Right-click menu offers
  Init, Update (pinned), Update --remote, Sync URL, and Show in
  Finder. "Open as profile" left for V2 — that needs the
  ProfileEditor to accept a prefilled-path open mode. Changes-tab
  inline pointer summary also V2.
