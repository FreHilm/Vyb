## Goal

`Shift+Alt+F` (and a tab-bar / right-click action) reformats the
active editor buffer through Prettier. Picks up the project's
local Prettier config when one exists, falls back to sensible
defaults otherwise. Saves the round-trip to the shell or a
separate editor when the user just wants their JSON/TS prettified.

## Acceptance Criteria

- [ ] `Shift+Alt+F` formats the active file in place. Cursor
      position roughly preserved (or restored to the same logical
      offset after reformat).
- [ ] Toolbar button next to Save / Save As that does the same.
- [ ] Honours the repo's `prettier.config.*`, `.prettierrc`, or
      `package.json#prettier` block when present (Prettier's own
      resolver handles this).
- [ ] Supports the file types Vyb already has CodeMirror modes for:
      JS, TS, TSX, JSON, CSS, HTML, Markdown. Skip Python (Prettier
      doesn't format it — show a no-op toast instead).
- [ ] Failed format (syntax error in the file) surfaces in a
      non-blocking toast, doesn't clobber the buffer.
- [ ] Setting in Settings → Editor (or Functions): "Format on
      save" toggle, default off.

## Notes

- Prettier as an npm dependency is heavy (~5MB). Two options:
  (a) bundle Prettier with the app and run in the main process
  (simplest, single source of truth, but inflates the dmg),
  (b) shell out to `npx prettier` (smaller bundle, slower first
  invocation, requires node in the user's PATH).
  Recommend (a) — Prettier's stdin/stdout API is cheap to invoke
  and the user experience is identical across machines.
- Add Prettier to vite.main.config.ts externals so it isn't bundled
  into the renderer.
- Use `prettier.format(source, { filepath, ...resolvedConfig })` —
  the `filepath` arg lets Prettier infer the parser automatically.
- Cursor preservation: compute the cursor's offset in lines/columns
  before format, snap to the same line+column after. Don't try to
  do a precise text-position match — Prettier rewrites; an
  approximate restore is good enough.
