## Goal

Two related context-preserving editor bits VS Code calls
"Breadcrumbs" (path bar at the top of the editor) and "Sticky
scroll" (current scope's headers pinned at the top of the viewport
while scrolling).

Both make it easier to keep your bearings inside a large file:
breadcrumbs answer "where am I in the project + file?", sticky
scroll answers "which function/class is the visible code part of?".

## Acceptance Criteria

- [x] **Breadcrumbs row** above the tab bar showing the file's path
      from the working directory; each segment is a clickable
      button that drives the existing `revealRequest` path.
- [ ] Last breadcrumb showing current symbol scope. *(V2 — needs
      cursor-position tracking + a separate symbol resolver per
      language; the sticky-scroll plugin already does this work
      from the viewport top, but the breadcrumbs would need it
      from the cursor instead.)*
- [x] **Sticky scroll** plugin: walks the Lezer syntax tree from
      the viewport's top line, collects up to 3 enclosing scope
      declarations, renders them as a floating overlay anchored to
      the editor's top edge. Click any row to scroll back to that
      declaration. Supports JS/TS function/class/method/interface/
      enum/namespace, Python def/class, Markdown ATX + Setext
      headings.
- [x] Toggles in Settings → Functions: "Editor breadcrumbs",
      "Sticky scroll". Both default on.
- [x] Plays nice with the blame gutter — the sticky overlay is
      positioned at the editor's top edge, gutter content sits
      below it, alignment unaffected.

## Notes

- Scope detection: the cheap path is regex per language (top-level
  `function`/`class` for JS/TS, `def`/`class` for Python, `#` for
  markdown). The richer path uses CodeMirror's syntax tree —
  `syntaxTree(state).resolveInner(cursor.from)` and walk up looking
  for nodes named `FunctionDeclaration` / `ClassDeclaration` etc.
  Start with the tree-walk approach for JS/TS, fall back to regex
  for Python/CSS/HTML/Markdown where the CM language modes are
  thinner.
- Sticky scroll: CodeMirror doesn't ship a built-in. The standard
  pattern is an `EditorView` plugin that watches `viewportChanged`
  and renders an absolutely-positioned overlay above the scroller
  containing copies of the in-scope declaration lines. Style with
  a subtle bottom border + slightly elevated background.
- Breadcrumbs row needs ~24px of vertical space — adjust the tab
  bar / editor flex layout accordingly.
- The "click breadcrumb segment to reveal in tree" action reuses
  the same `revealRequest` path T-043 wires up for "reveal current
  file in tree".

## Progress

- 2026-05-14: Shipped. Two new bits of editor furniture.
  
  **Breadcrumbs**: a `.file-breadcrumbs` row above the tab bar
  rendered when `breadcrumbs` prop is true. Splits the active
  tab's path against the working directory and renders each
  segment as a button that calls `setRevealRequest` with the
  accumulated path — the existing FileTreeNode reveal pipeline
  walks ancestors and scrolls the leaf/dir into view.
  
  **Sticky scroll**: new `src/renderer/lib/sticky-scroll.ts`
  exports a CodeMirror ViewPlugin. On each `viewportChanged` /
  `docChanged` / `geometryChanged` (plus a raw scroll listener to
  catch in-viewport scrolls that don't trigger an update), it
  finds the line at the viewport top, walks
  `syntaxTree(state).resolveInner(...).parent` and collects nodes
  whose `type.name` matches the scope set
  (FunctionDeclaration / ClassDeclaration / MethodDeclaration /
  ArrowFunction / InterfaceDeclaration / EnumDeclaration /
  NamespaceDeclaration / Python's FunctionDefinition + ClassDefinition +
  AsyncFunctionDefinition / Markdown's ATX/Setext headings). The
  overlay div is appended to `view.dom`, positioned absolutely at
  the editor's top edge, and each row's click dispatches a
  selection to that line + scrollIntoView.
  
  Both settings live in Settings → Functions and default on.
  Sticky scroll's enable state is read at editor mount time
  (toggling it takes effect on the next file open) — keeping the
  plugin in/out of the live extension array would require a
  compartment.
