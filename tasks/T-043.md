## Goal

Close the most-felt gaps between Vyb's editor + file tree and what
VS Code offers, packaged as one focused batch. Each sub-feature is
small on its own but collectively they're what makes the editor
feel "good enough to stay in" during agent work instead of
bouncing out to VS Code.

## Acceptance Criteria

- [ ] **Find & Replace** — `Cmd+Alt+F` (or a toolbar button) opens
      the existing `@codemirror/search` panel in Replace mode. Same
      panel handles regex / case / word toggles that come with the
      CM6 extension. `Cmd+F` continues to open Find-only.
- [ ] **Cmd+P quick file open** — global shortcut opens a fuzzy
      file-picker over the active profile's working directory.
      Honours `.gitignore` (skip `node_modules/`, `.git/`, etc.).
      Arrow-keys to navigate, Enter opens in the editor, Esc
      dismisses.
- [ ] **Tab right-click menu** — context menu on a file tab with:
      Close, Close Others, Close to the Right, Close All, Reveal in
      Finder, Copy Path, Copy Relative Path.
- [ ] **Reveal in tree** — a button (and/or `Cmd+Shift+E`) that
      jumps the file tree to scroll the currently-active tab into
      view and select it. Reuses the existing `revealRequest`
      mechanism that already drives terminal click-to-reveal.
- [ ] **Git decorations in tree** — file tree rows whose paths
      appear in `gitChangedFiles` get a colour cue + small badge:
      M (modified) yellow, A (added) green, D (deleted) red,
      ? (untracked) grey, R (renamed) blue. Refreshes when the
      Git panel reloads (i.e. on the same `reloadEpoch` it already
      uses).

## Notes

- The `@codemirror/search` panel already supports Replace — we just
  don't bind it. Look at `openSearchPanel` and pass the right
  initial state, or expose a small toolbar trigger.
- Quick-open list: parent process can shell out to `git ls-files`
  for tracked files (fast and gitignore-aware for free); fall back
  to a recursive walk if not a git repo. Fuzzy match in the
  renderer; result list capped (e.g. top 50) so the modal stays
  responsive.
- Tab right-click: existing context-menu CSS classes (`.file-ctx-item`)
  are reusable.
- Reveal in tree: `revealRequest` in FileExplorer already handles
  expanding ancestors + scrolling the leaf into view. Just need a
  trigger from a toolbar button / shortcut.
- Git decorations: don't re-fetch on every render — piggyback on
  whatever cadence the status bar uses today (10s poll + manual
  reload epochs). One Map<path, status> in FileExplorer state.
