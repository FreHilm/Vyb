## Goal

Close the most-felt gaps between Vyb's editor + file tree and what
VS Code offers, packaged as one focused batch. Each sub-feature is
small on its own but collectively they're what makes the editor
feel "good enough to stay in" during agent work instead of
bouncing out to VS Code.

## Acceptance Criteria

- [x] **Find & Replace** — `Cmd+Alt+F` (basicSetup's searchKeymap)
      and a new "Find/Replace" toolbar button both open the
      `@codemirror/search` panel with Replace mode visible. `Cmd+F`
      still opens Find-only.
- [x] **Cmd+P quick file open** — global keybinding opens a fuzzy
      picker over the active profile's directory via a new
      `file:listProject` IPC (uses `git ls-files` when possible).
      ↑/↓ navigate, Enter opens, Esc closes.
- [x] **Tab right-click menu** — Close / Close Others / Close to
      the Right / Close All / Reveal in Finder / Copy Path / Copy
      Relative Path.
- [x] **Reveal in tree** — toolbar button + `Cmd+Shift+E` keyboard
      shortcut, drives the existing `revealRequest` so the tree
      expands ancestors and scrolls the leaf into view.
- [x] **Git decorations in tree** — modified/added/deleted/
      untracked/renamed files get colour-coded names and a small
      one-character badge. Refreshes every 10s plus whenever the
      `refreshKey` bumps.

## Notes

- The `@codemirror/search` panel already supports Replace — we just
  don't bind it. Look at `openSearchPanel` and pass the right
  initial state, or expose a small toolbar trigger.
- Quick-open list: parent process can shell out to `git ls-files`
  for tracked files (fast and gitignore-aware for free); fall back
  to a recursive walk if not a git repo. Fuzzy match in the
  renderer; result list capped (e.g. top 50) so the modal stays
  responsive.
- Tab right-click: existing context-menu CSS classes (`.file-ctx-item`)
  are reusable.
- Reveal in tree: `revealRequest` in FileExplorer already handles
  expanding ancestors + scrolling the leaf into view. Just need a
  trigger from a toolbar button / shortcut.
- Git decorations: don't re-fetch on every render — piggyback on
  whatever cadence the status bar uses today (10s poll + manual
  reload epochs). One Map<path, status> in FileExplorer state.

## Progress

- 2026-05-14: Shipped. Five sub-features in one batch:
  * New `QuickOpenDialog` component mounted in `App.tsx`, fed by a
    new `file:listProject` main-process IPC. The IPC prefers
    `git ls-files --cached --others --exclude-standard -z` (fast +
    gitignore-aware), falling back to a BFS walk that skips
    `node_modules`, `.git`, `dist`, `build`, etc. Capped at 10k
    files. Renderer-side fuzzy scoring biases toward word
    boundaries and basename matches.
  * Cmd+P keybinding registered in App.tsx with capture: true so it
    pre-empts xterm and editor handlers. Opening a file ensures
    `filesViews`/`filesRunning` are set for the active view, then
    drives the existing `pendingFileOpen` ref.
  * Tab right-click renders a `.file-tab-ctx-menu` overlay with all
    six standard items; close-on-outside-click handled by a small
    window mousedown listener.
  * Reveal-in-tree button next to Save/Blame, plus `Cmd+Shift+E`
    keybinding scoped to FileExplorer's mount lifecycle. Both call
    `setRevealRequest` which the existing `FileTreeNode` already
    consumes to expand ancestors + scroll into view.
  * Git decorations driven by a 10s poll of `getGitChangedFiles`,
    mapped to absolute paths and threaded down through
    `FileTreeNode` as a `Map<string, string>`. Per-row CSS class
    `.git-modified`/`-added`/`-deleted`/`-untracked`/`-renamed`
    colours the name; a small badge (M/A/D/?/R) renders right.
  * Find/Replace toolbar button calls `openSearchPanel` and
    synthesises a `Mod-Alt-f` keydown against the editor DOM so
    basicSetup's searchKeymap toggles Replace mode visible —
    `@codemirror/search` doesn't expose that command directly.
