## Goal

Drag-and-drop interactive rebase for a range of commits on top of HEAD
(or onto any other commit). Per-commit actions: pick, reword, squash,
fixup, edit, drop. Driven by a Vyb-owned editor that replaces the
default `GIT_SEQUENCE_EDITOR`.

## Acceptance Criteria

- [x] Tree tab right-click on a commit → "Interactive rebase from
      <sha>…" opens a list of the commits between that one
      (inclusive) and HEAD, in git's oldest-first todo order.
- [x] User can drag rows to reorder; per-row action picker offers
      pick / reword / edit / squash / fixup / drop.
- [x] On submit, Vyb writes the prepared todo to a temp file +
      writes a platform-specific shim (.sh on POSIX, .cmd on
      Windows) that copies it into the path git passes to
      `GIT_SEQUENCE_EDITOR`. `GIT_EDITOR=true` keeps reword/squash
      message edits non-interactive — V1 accepts git's default
      combined messages.
- [x] Conflicts and stop-for-edit pauses fall through to the
      existing rebase banner (via `collectConflicts` and a
      `.git/rebase-merge/` check). Continue / Abort buttons already
      drive the existing `gitRebaseContinue` / `gitRebaseAbort`
      IPCs unchanged.

## Notes

Implementation pattern: set `GIT_SEQUENCE_EDITOR` to a tiny helper
binary (or `sh -c "cat <vyb-tmp-todo> > "$1""`) that writes our
prepared list and exits 0. Similarly `GIT_EDITOR` for reword stops.

## Progress

- 2026-05-14: Shipped. New `git:rebaseInteractive` IPC validates the
  todo list line-by-line (`/^(pick|reword|edit|squash|fixup|drop)
  <sha>(?: .*)?$/`), performs the same dirty-tree + detached-HEAD
  pre-flight as the existing `gitRebase` handler, then runs
  `git rebase -i <base>^` (falling back to `--root` for root
  commits) with a platform-specific sequence-editor shim that
  copies our prepared todo over the path git passes. POSIX writes
  `seq-editor.sh` (chmod 755), Windows writes `seq-editor.cmd`.
  Cleanup runs in a `finally` regardless of outcome.
  
  Conflict and stop-for-edit pauses fall through to the existing
  rebase banner: conflicts surface via `collectConflicts`, edit
  stops via a `.git/rebase-merge/` existence check that also
  returns `error: 'conflict'` with an empty conflictedFiles array.
  Continue / Abort work unchanged.
  
  New `RebaseInteractiveDialog` component lives in its own file
  (HTML5 DnD for reorder, same idiom as `Sidebar.tsx`). The op is
  routed through a new optional `onRebaseInteractive` field in
  `useGitRefOps.RefOps`; GitTree provides the implementation
  (closing over its `commits` state) and renders the dialog locally.
  
  V2: reword message editor (currently keeps the original
  message), `--onto` target picker, `exec` rows, keyboard-only
  reorder, `--rebase-merges` support.
