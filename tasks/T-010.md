## Goal
When a file is open in the file editor, add an Edit menu containing:

- File: Save, Save As, Undo, Redo
- Clipboard: Cut, Copy, Paste, Select All (each behaving as in any standard editor)
- Find / Search (open the editor's search panel)

## Acceptance Criteria

- [x] An "Edit" menu lives in the application menu bar with three groups: File (Save, Save As), Undo/Redo, Clipboard (Cut, Copy, Paste, Select All), Find / Search.
- [x] Items are greyed out when no file is open in the editor; Save in particular is greyed out unless the active file is modified.
- [x] Clicking each menu item dispatches the action to the active CodeMirror editor (no key accelerators on the menu, so terminal Cmd+C / Cmd+Z keep working).
- [x] CodeMirror's built-in shortcuts (Cmd+Z, Cmd+C, Cmd+V, Cmd+X, Cmd+A, Cmd+F) continue to work inside the editor as before.

## Notes

- The application menu uses click handlers + IPC instead of `role: 'copy'` etc. because main.ts already documents that role-based accelerators on macOS install OS-level key handlers that intercept keys before xterm.js sees them. Without accelerators on the menu, CodeMirror's keymap (via `basicSetup`) still handles the same shortcuts when the editor is focused, while terminals retain native key handling.
- Two new IPC channels: `EDIT_MENU_ACTION` (main → renderer, carries the action name) and `EDIT_MENU_STATE` (renderer → main, carries `{hasFile, canSave}` so main can rebuild the menu with correct enabled flags).
- Added `@codemirror/commands` and `@codemirror/search` as direct dependencies; both were already present transitively via the `codemirror` meta-package, so no new licensing concern.
