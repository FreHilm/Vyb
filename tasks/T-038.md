## Goal

Show a small avatar (gravatar by default) next to each commit row in
the Tree tab so a long graph scans visually by author rather than by
reading text.

## Acceptance Criteria

- [x] Each commit row gets a 16 px avatar in the author column.
- [x] Avatars resolved from the gravatar URL using the lowercase MD5 of
      the trimmed email. Hash cache is in-memory; HTTP caching is left
      to the browser (gravatar serves long Cache-Control headers).
- [x] Falls back to a generated colour-from-email circle with the
      author's initials on 404 / offline (gravatar's `d=404` mode +
      onError handler routes through `failedHashes`).
- [x] Toggleable in Settings → Functions ("Show author avatars",
      default on).

## Notes

Gravatar fetch should be best-effort with a tight timeout (e.g. 3 s)
so the graph never blocks rendering on network.

## Progress

- 2026-05-14: Shipped. New `AuthorAvatar` component renders a
  gravatar (or initials-circle fallback) next to each commit row;
  threaded through GitChangesPanel → GitTree as `showAuthorAvatars`,
  with a toggle in Settings → Functions (default on).
- 2026-05-14: Initial pass routed MD5 through the preload (Node
  crypto). The vite-bundled preload couldn't resolve the import
  reliably and the renderer crashed on first invoke; rolled back to
  initials-only as a hotfix.
- 2026-05-14: Restored. Replaced the preload bridge with a pure-JS
  MD5 in `src/renderer/lib/md5.ts` (~120 lines, no deps). Verified
  against six standard test vectors including a cross-block input
  and a representative email address. AuthorAvatar now calls
  `md5(email)` directly in the renderer — no IPC, no crypto module,
  no preload involvement — so the gravatar path works without any
  cross-process risk. Failed-hash + URL-hash caches stay
  module-level so a long scroll doesn't re-hash or re-attempt 404s.
