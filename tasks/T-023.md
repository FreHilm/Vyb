## Goal

Today staging is all-or-nothing per file. Add the ability to stage (or
unstage) individual hunks and individual lines from a file's diff, so a
user can break a noisy working copy into clean, focused commits without
juggling the index by hand.

## Acceptance Criteria

- [x] Each hunk header in the diff view has a "Stage hunk" / "Unstage
      hunk" action.
- [x] Selecting a line range inside a hunk exposes "Stage selection" /
      "Unstage selection".
- [x] The action sends the matching hunk/lines through
      `git apply --cached` (or `--reverse --cached`) so the index ends
      up at exactly the chosen subset.
- [x] After staging, the file shows up in both the staged and unstaged
      lists with the appropriate per-side diffs.
- [x] Works for added, modified, and deleted files; gracefully refuses
      on binary files.

## Notes

Likely needs a new IPC + a small hunk-patch builder. Test cases should
cover CRLF normalisation and trailing-newline preservation.

## Progress

- 2026-05-14: Shipped. New `hunk-patch.ts` helper builds a partial
  unified diff from a `Set<DiffLine index>`: unselected `+` lines are
  dropped, unselected `-` lines are demoted to context, and hunk-header
  line counts are recomputed so `git apply --cached` (plus `--recount`
  belt-and-suspenders) accepts the patch. New `git:applyPatch` IPC
  streams the patch to `git apply` via stdin; `--reverse` flips the
  direction for unstage. Hunk header band gets a hover-revealed
  Stage/Unstage button in unified + split modes. Unified mode also
  supports drag-select line ranges with a sticky "Stage selection"
  action bar; Esc cancels. Binary files show a guard message and skip
  the affordances. Split-mode drag-select deferred to V2 — two-column
  selection semantics need their own design.
