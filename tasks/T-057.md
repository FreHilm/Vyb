## Goal

Spun off from T-056. Once an agent profile can span multiple
directories, those directories may be separate git repositories. The
StatusBar today assumes one repo (the profile's single
`workingDirectory`). Extend the git client to understand a set of repos.

## Background

- `StatusBar.tsx` calls `window.api.getGitStatus(profile.workingDirectory)`
  and renders branch / staged / modified / ahead-behind / stash / last
  commit / remote for that one cwd.
- Main side: `computeGitStatus(cwd)` in `src/main/ipc-handlers.ts`
  (~973+) runs all git commands against a single cwd, with a cache +
  dedupe layer and 10s polling.
- No notion of "this profile has 2+ repos" exists yet.

## Acceptance Criteria

- [ ] Git status resolves per directory for a multi-path profile
      (only the dirs that are actually git work-trees).
- [ ] StatusBar shows either an aggregate or a per-repo
      switcher/dropdown when a profile has more than one repo.
- [ ] Fetch button targets the right repo(s).
- [ ] Polling/cache still dedupes and doesn't multiply git spawns
      unreasonably as repo count grows.
- [ ] Single-repo profiles look and behave exactly as today.

## Open Questions

- [ ] Aggregate view vs. per-repo switcher vs. both?
- [ ] How to detect which of the profile's paths are git roots
      (walk up to `.git`, or `git rev-parse --show-toplevel` per path)?
- [ ] Does the remote-link / branch display make sense aggregated, or
      must it be per-repo only?
